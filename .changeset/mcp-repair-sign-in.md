A remote MCP server that asks for a sign in no longer ends up disconnected behind the proxy, and nothing in Memnox signs a person out of a tool. `memnox mcp signin <server>` signs in through Memnox in the browser and keeps the sign in in the OS store, which the proxy sends and renews, so the server connects and its calls stay ruled on. Taking a remote server into the hub now asks it first and moves it behind the proxy only once it has answered there; one that wants a sign in, or did not answer, is left exactly as the person set it up. `memnox mcp repair` finds the servers already broken and hands them back to the agent as their own address, asking before it changes anything. `mcp unwrap` and `uninstall` now put remote servers back as well as local ones. A server that will not connect behind Memnox is told to the person once, on the waiting feed, on its hub card and in `memnox doctor --servers`, and the agent's own server list says why and what to run in place of a bare status code. A refused credential, a missing secret and a local server whose command did not start are each said as what they are. `memnox mcp repair` offers the sign in through Memnox first and hands back only what that did not mend. `memnox mcp signin` takes `--client-id` and `--port` for a server that registers no new app. The daemon answers `mcp-sign-in`, which opens the browser and writes what the sign in came to onto the server's card, and `mcp-hand-back`, which is a signed proposal; the hub view carries `trouble` so a screen offers both only where they apply. A sign in no longer hangs after the browser comes back: the loopback page closes the connections a browser leaves open, every sign in request is bounded, and the sign in is sealed in a file under the Memnox home with only its key in the OS store, so a long token never meets an OS store's limit. The browser shows a Memnox page with the outcome, and `repair` takes servers one at a time with Enter to skip.
